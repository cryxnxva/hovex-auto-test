# honex-auto-test

Мини-парсер объявлений Avito по артикулам товаров HONEX.

Скрипт выполняет поиск каждого артикула на Avito, отбирает объявления в состоянии «Новое» из Москвы и Московской области, сортирует их по возрастанию цены, оставляет 5 самых дешёвых по каждому артикулу и сохраняет результат в `result.xlsx` (одна строка — одно объявление).

## Требования

- Python 3.10+ (проверено на 3.12).
- Зависимости в `requirements.txt`:

```
requests>=2.31.0
beautifulsoup4>=4.12.2
pandas>=2.1.0
openpyxl>=3.1.2
```

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

После запуска в корне проекта появится файл `result.xlsx`.

> **Windows-примечание.** Если в логах вместо кириллицы выводится `?` или возникает `UnicodeEncodeError` (консоль по умолчанию в cp1252/cp866), задайте UTF-8 для вывода: `$env:PYTHONIOENCODING='utf-8'` перед `python main.py`.

Если живой запрос к Avito заблокирован (HTTP 429/403, капча, анти-бот страница) — скрипт не падает: он автоматически читает сохранённые HTML-страницы из `test_data/` и обрабатывает их по той же логике. Обход капчи и блокировок в задание не входит и не реализован.

## Конфигурация

Все настройки — в `config.py`, класс `AppConfig` (frozen dataclass). Артикулы задаются в поле `articles` классом `SearchArticle(code, description)`.

### Как задаётся регион

Два уровня:

1. **URL поиска** — поле `region` (по умолчанию `"rossiya"`, вся Россия). Меняется на `"moskva"` при необходимости.
2. **Фильтр по локации** — поле `allowed_location_keywords = ("москв", "москов", "подмосков")`. Объявление попадает в результат, только если в его локации встречается один из этих маркеров. Так покрываются «Москва» и «Московская область» при поиске по всей России.

### Как задаётся состояние товара

Поле `allowed_conditions = ("Новое",)`. Объявление проходит фильтр, если значение параметра состояния содержит одну из этих подстрок (например, «Состояние: Новое»). Товары б/у, «Как новый» и т.п. отсеиваются.

### Как задаётся сортировка по цене

- Поле `max_results_per_article = 5` — сколько самых дешёвых сохранять по каждому артикулу (если подходящих меньше — сохраняются все).
- Цена извлекается как число (`int`), объявления без числовой цены («Договорная», «Цена не указана») **не участвуют** в отборе.
- После фильтров объявления сортируются по цене по возрастанию, каждой строке присваивается `price_rank` = 1..N.
- Повторяющиеся объявления (одинаковая ссылка) в рамках одного артикула удаляются — остаётся первое (самое дешёвое) вхождение.

### Прочие параметры

| Параметр | Назначение |
|---|---|
| `headers` | User-Agent и Accept для запроса к Avito (без логинов и токенов) |
| `timeout_seconds` | Таймаут сетевого запроса, `15.0` |
| `use_live_requests` | `True` — живой запрос + fallback; `False` — только локальные HTML (воспроизводимый тест) |
| `test_data_dir` | Каталог с локальными HTML-страницами выдачи, `test_data/` |
| `output_file` | Имя файла результата, `result.xlsx` |

## Логика работы

1. Для каждого артикула формируется URL `https://www.avito.ru/{region}?q={артикул}` и выполняется GET-запрос.
2. Некорректный ответ (статус не 200, капча, страница без карточек объявлений) или сетевая ошибка → чтение `test_data/{артикул}.html`. Кодировка определяется автоматически: UTF-8 → cp1251 → с подстановкой.
3. HTML разбирается в карточки объявлений (fallback-цепочки селекторов в `parser.py`).
4. Применяются фильтры (цена, состояние, регион), сортировка, дедупликация, отбор топ-N.
5. Формируется DataFrame и экспортируется в `result.xlsx`.

Колонки: `article`, `search_query`, `title`, `price`, `location`, `condition`, `url`, `price_rank`, `check_date`, `status`.

Если по артикулу ничего не найдено — добавляется строка со статусом **«не найдено»**; если страницу не удалось получить вообще (нет ни ответа, ни локального файла) — со статусом **«ошибка»**. В успешных строках статус — **«ok»**.

## Структура проекта

```
main.py       # точка входа: AvitoClient (источники HTML + graceful degradation),
              # SearchPipeline (фильтры, сортировка, топ-5, статусы),

README.md

```

## Ограничения и примечания (по условиям ТЗ)

- CAPTCHA, авторизация и обход блокировок **не** реализованы — при блокировке выполняется только аккуратный переход на локальные HTML.
- В коде нет логинов, cookies, токенов и клиентских данных HONEX.
- Живой ответ Avito в рамках проверки блокируется (HTTP 429/фирволь), поэтому фактический `result.xlsx` собран из тестовых HTML-страниц, имитирующих реальную выдачу: по 5 валидных строк на каждый артикул. Подложка включает краевые случаи: товары б/у, другие регионы (СПб, Казань, Екатеринбург), «Договорная», дубли по ссылке, более 5 подходящих объявлений.

## Фактические затраты времени, сложности и ИИ

**Время.** Работа велась интерактивно, с проверкой пользователем после каждого шага; суммарно уложились в лимит задания (≈1,5–2 часа): планирование и scaffold ~15 мин, `config.py` ~10 мин, `parser.py` ~20 мин, тестовые HTML-фикстуры ~20 мин, `main.py` ~25 мин, верификация с реальной сетью + фикс ~15 мин, README ~10 мин.

**Сложности.**
1. *Живой запрос к Avito блокируется* — причём по-разному: HTTP 429, 403 и даже HTTP 200 с анти-бот страницей без карточек. Решение — детект «пустой» выдачи по маркерам карточек и graceful degradation на локальные HTML.
2. *Разметка Avito нестабильна* — для каждого поля выстроены fallback-цепочки селекторов (по `itemprop` и `data-marker`).
3. *Кодировки* — сохранённые страницы могут быть в cp1251; консоль Windows не печатает кириллицу. Решено автоопределением кодировки и `PYTHONIOENCODING=utf-8`.
4. *Пограничные данные* — «Договорная» вместо цены, дубли ссылок, «Как новый», «Московская область» не матчилась ключевым словом «москв».

**Использование ИИ.** Код написан в диалоге с AI-ассистентом (opencode): архитектура модулей, реализация парсера и пайплайна, генерация реалистичных HTML-фикстур, поиск и исправление багов (ключевые слова локации, детект пустой выдачи). Каждый шаг проверялся и согласовывался с пользователем; финальное решение и интерпретация требований — за пользователем.
